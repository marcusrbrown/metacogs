# Hypotheses

Upstream concepts and their current status. A concept is a `hypothesis` until it has a retained baseline failure and a held-out pass; `red-candidate` marks concepts entering the first RED cycle; `red-retained` marks concepts whose baseline failures met the RED bar and are retained (see `evals/reports/<concept>/red.json`), making them eligible for a skill and a GREEN run; `green-miss` marks a concept whose one-shot GREEN read missed a bar (see `evals/reports/<concept>/green.json`, or `green.epoch<N>.json` for a superseded epoch): the held-out set is burned for that epoch and a retry needs a new epoch and a new held-out set; `green` marks a read that met every bar; `green (human review pending)` marks one whose machine verdict is green while the human review of the judge verdicts is unfinished; `pilot` marks a concept whose pilot (`evals/<concept>/pilot/`) is under way before any skill exists; `not-reproduced` marks a pilot whose baseline did not show the failure the concept targets, `closed-instruction` one whose skill did not beat a one-line instruction that was itself effective (the instruction ships as an `AGENTS.md` recommendation), and `inconclusive` one where neither intervention met its bar (nothing ships); all three end the concept without a skill. `dropped` marks a concept probed by hand on a task built for it, where the method added nothing over a plain prompt (nothing ships); `rejected` marks one whose upstream framing conflicts with this repository's contracts or with what a stateless tool can do; `excluded` marks one that is not built because of what it frames.
